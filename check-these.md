# Verified review issues and fixes

Running record of review findings checked against the code in `26.3`, their disposition, and the changes made. Use the issue IDs below when later reports overlap these findings. The other `26.*` projects are candidates for the same changes, but each needs its corresponding code and loader APIs checked before applying a fix. This record does not claim that those projects have been reviewed or changed.

## Batch 1: dead code, efficiency, and expected way

Sources: [Dead code](review-Dead-code.md), [Efficiency](review-Efficiency.md), and [Expected way](review-Expected-way.md). IDs combine the report abbreviation with its original finding number; gaps in numbering belong to the reports.

Validation: the user reports that builds and GameTests succeed after this batch. The agent did not run builds or tests. A result for the development-client `/ssclienttest` checks has not been reported. Performance improvements are inferred from eliminated work, not benchmarked.

### Dead code and duplication

| ID | Verified issue | Fix and disposition |
| --- | --- | --- |
| DC-01 | The two client deposit rules repeated targeting work but had the same cancellation result as the generic modified-click rule. | Deleted `DepositIntoClickedStackRule` and `DepositIntoAdjacentStackRule`. Removed the client context's unused targeting data and updated both loaders' callers. Gesture checks now assert cancellation rather than which deposit rule won. Target and cell selection remain server-side. |
| DC-05 | Persisted field names were repeated across storage, block entities, and migration. | Exposed the owning constants and used them in migration field collection, saving, and client validation. Retained rejection of top-level `SetAside`: malformed wire input can contain it, and removing it from raw field collection would hide it from validation. The review's claim that this check cannot trigger was rejected. |
| DC-07 | Some helpers were unused, and some convenience overloads existed only for tests. | Deleted `AutomationActor.is`, the automation-only `WorldEdits.isProtected` overload, the five-argument `placeChecked`, the one-argument pile permanence setter, and the gallery permission-level getter. Tests now supply final collision shapes and explicit actors, or read immutable settings. The reviewed Storage three-argument and Bar one-argument extraction overloads were already absent. Retained useful test seams: render override isolation, config-path inspection, synchronized-state inspection, and serialization probes. |
| DC-10 | Successful interaction feedback repeated the same playback and extraction completion code. | Added `StackSounds.play` and shared successful extraction feedback through `finishExtraction`. Kept separate mutation branches for the three movement models. Sound volume and resource-pack behavior did not change. |
| DC-12 | Some comments and log messages described removed behavior or the wrong method. | Corrected Singles deposit-support documentation, removed obsolete synchronized/server override descriptions from render-profile documentation and warnings, and corrected the storage loader count. Bar deposit documentation and annotation, orphan ceiling comments, and the `SlotAccess` adapter description were already corrected or accurate. |
| DC-14 | Common code looked up registered values while loader registries retained some unread references. | Removed unread sound holder fields while retaining the registration calls. Kept loader block references needed for block-entity registration and native deferred registration. Registry supplier installation was not introduced. Hot-path type lookup is addressed by EW-10. |
| DC-16 | Config code duplicated namespace validation, a clamp helper, and a pile-height limit alias; gesture decoding repeated enum lookup. | Consolidated packet namespace validation, used `Mth.clamp` and `ServerConfig.MAX_PILE_HEIGHT`, and routed validated gesture ordinals through `StackMode.fromOrdinal`. Kept the existing namespace API call and VarInt-size helper rather than substituting APIs whose target-version signatures were not established. Receive-side namespace length was already bounded by `readUtf` and constructor validation; no missing length guard was found. |

### Efficiency

| ID | Verified issue | Fix and disposition |
| --- | --- | --- |
| EF-01 | Headroom capacity scans repeated growth authority checks for candidate slots; positional runs checked growth before support. | Moved staged support checks ahead of growth in Singles and Bar. Shared shape-independent growth preflight in `StackRun` and cached automation permission only within a scoped bulk insertion query. Height, enablement, and replaceability still read current state; collision remains per position. Later operations and commit placement retain authorization checks. No tick-wide permission cache was added. |
| EF-02 | Automation slot access repeatedly located the base block and its transaction ledger. | Added direct base-entity access to resolved runs, removing redundant world lookups. Base adapters return their own ledger without another attachment lookup. Bulk insertion, Fabric extraction, and Fabric iteration delegate to the base ledger once. Retained external slot views still resolve the current run when used. Native transaction staging and rollback remain loader-specific. |
| EF-03 | Every settlement group eagerly converted nonempty item-component patches to strings for sorting. | Sort keys retain the patch and create a memoized string only when item ID and damage tie and both patches are nonempty. Existing ordering, identity grouping, and settlement behavior are preserved. |
| EF-04 | Slot mutations call `setChanged`, and runs separately publish comparator changes. | The two mod call paths are confirmed, but duplicate native comparator notification in the target version was not independently established. Deferred: no dirty-marking or comparator publication change was made. Confirm the target native contract before selecting a single notification mechanism. |
| EF-05 | Bar render extraction resolved textures and sprites and rebuilt presentation lists every frame. | Cached prepared Bar presentation in the block entity's render cache. Content updates discard it; a resource-generation stamp expires retained block caches after reload. Clearing the sprite-region map alone is not treated as sufficient invalidation. Extended `/ssclienttest` to check reuse and both invalidation boundaries. |
| EF-06 | Bar and grid render preparation explicitly looked up light after superclass render-state extraction. | Removed the redundant light lookup and Bar's private light field. Both presentation paths now use inherited `lightCoords`; frame lighting remains refreshed independently of cached presentation. |
| EF-07 | Each member block cached a separately resolved copy of its whole run. | Cached one resolved run instance on every current member for the same tick. Retained structural invalidation for affected runs and added a shared-instance check after growth. This removes repeated traversal; whole-run comparator fill summation still exists. |
| EF-08 | Singles and Bar shape rebuilding repeatedly optimized a growing union with `Shapes.or`. | Accumulated boxes with `Shapes.joinUnoptimized` and optimized once after the loop. Existing occupancy/rotation shape caches and invalidation remain in place. |

### Expected vanilla and loader mechanisms

| ID | Verified issue | Fix and disposition |
| --- | --- | --- |
| EW-02 | Stack block-use methods ignored the interaction handler's unhandled result and always consumed the click. | Native use methods consume handled server gestures and return `PASS` otherwise. Recognized client gestures remain consumed by loader callbacks. Ordinary extraction attempts still consume the click even when no item moves. Extended existing interaction checks for off-hand use, unhandled modified empty-hand clicks, occupied-hand permanence mode, and empty extraction attempts. |
| EW-03 | Reading rotation could apply a pending block-entity rotation and mutate the world. Storage joining a pile could also change facing after placement. | Removed pending rotation state and application hooks. Rotation getters are pure; setters change native facing through `level.setBlock`. `StackPlacement.stateFor` chooses neighboring Storage facing before placement. Pile adoption retains permanence without a second facing edit. Singles shape invalidation remains, and growth checks now cover inherited facing. |
| EW-05 | Reload paths did not refresh command trees when gallery visibility or permission changed; command and native reload logic diverged. | Added one synchronous server-thread `reloadPolicy` operation used directly by `/ss reload` and scheduled by native callbacks. Changed gallery enablement or permission resends commands to connected players. Changed client settings rebuild and send the config snapshot; unchanged policy does no synchronization work. Extended existing config checks for gallery enablement, permission changes, and disabling after reload. |
| EW-06 | Saved inventory uses a nested `Items` compound rather than a conventional top-level item list. | Layout confirmed; external tool failures were not demonstrated. Deferred as a separate format/migration decision. This batch preserves the saved layout, unreadable-entry retention, migration behavior, and atomic client validation. If changed later, convert the immediately preceding release's saved form in the migration layer and retain raw unreadable entries. |
| EW-08 | Fabric uses `FabricBlockEntityTypeBuilder`. | Its alleged deprecation for the pinned target was not established; builder use alone is not a verified defect. No change. Do not infer Fabric constructor availability from NeoForge's constructor use. |
| EW-09 | Fabric config loading installed its backend and published settings internally, duplicating the facade's work. | `JsonServerConfig.load`, `loadFor`, and `reload` now return settings without installation or application. The facade owns publication. Fixture setup explicitly installs/applies its backend and verifies that loading itself changes neither. Retained independent field fallback, clamping, and malformed-list-member filtering; a whole-record codec rewrite was not required. |
| EW-10 | `BlockType.of` scanned enum values and performed registry lookups to classify a block. | Added `StackBlock.type`, implemented by each stack block, and classified through `instanceof StackBlock`. Registered-instance lookups remain where an actual registered object is needed. |
| EW-11 | The server-only consultation guard used `ThreadLocal` despite its single-threaded call paths. | Replaced it with a plain boolean and documented the separate scopes of consultation, loader snapshot placement, and transfer-commit guards. Kept these guards distinct because they prevent different forms of reentry. |

### Carry-forward checks for other 26.* projects

- Match the affected behavior and call sites before applying these changes; line numbers and already-completed cleanup differ between projects.
- Preserve permission callbacks, actor attribution, staged support, cross-block transaction sharing, rollback, and structural cache invalidation when porting the automation changes.
- Keep native facing inheritance before placement and preserve Storage permanence and Singles rotation-aware support.
- Tie prepared Bar presentation to both content updates and resource reloads, while continuing to refresh lighting each frame.
- Update existing GameTests and orientation descriptions alongside each port. Build and GameTest success reported here applies to `26.3`; validate each other target separately, including its client checks.
- EF-04 and EW-06 remain deferred. EW-08 is unconfirmed. The qualified or rejected parts of DC-05, DC-07, DC-12, DC-14, DC-16, and EW-09 must not become automatic porting tasks.
